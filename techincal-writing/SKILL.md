# 명확한 한국어 기술 문서

독자가 수행할 행동, 적용 조건, 확인할 결과를 정확히 이해하도록 한국어 기술 문서를 작성하거나 교정한다. ASD-STE100 Simplified Technical English(STE)의 원칙을 참고한 한국어 작성 가이드이며, 공식 한국어 STE 표준이나 준수 인증이 아니다.

## 작업 범위와 의미 보존

- 사용자가 요청한 문서와 범위를 따른다. 기존 제목, 단계 번호, 표, 링크, 문체는 의미 전달에 필요한 부분만 수정한다.
- 교정은 의미를 보존한다. 요약·번역·내용 추가는 요청된 경우에만 수행한다.
- 수치, 단위, 비교 연산자, 부정, 의무와 권고의 강도, 선행 조건, 예외, 실행 순서, 동시 실행 여부, 경고 수준을 보존한다.
- 명령어, 코드, 경로, API 식별자, 설정 키, UI 표시 문자열은 그대로 유지한다. 오류 수정을 요청받았거나 근거가 확인된 수정이라면 변경 이유를 설명한다.
- 원문이 모호하면 주변 문맥과 제공된 자료에서 먼저 확인한다. 결정할 근거가 없으면 모호함을 남기고 필요한 확인 사항을 별도로 적는다. 임의의 시간·수치·주체·완료 조건을 만들지 않는다.

## 한국어 작성 규칙

### 용어와 지시 대상

- 같은 대상에는 같은 용어를 사용한다. 제품의 공식 명칭과 기존 용어집을 우선한다. 다른 개념을 편의상 같은 단어로 합치지 않는다.
- 전문 용어를 무조건 쉬운 단어로 바꾸지 않는다. 대상 독자에게 설명이 필요하면 첫 등장에 뜻을 풀어 쓴다.
- 누가 무엇을 하는지 모호하면 주체와 대상을 명시한다. 문맥상 분명한 주어를 모든 문장에서 반복할 필요는 없다.
- 지시어와 생략의 대상을 확인한다. “이를 제거하세요”, “확인 후 실행하세요”가 여러 대상을 가리킬 수 있으면 구체적인 이름을 쓴다.
- 긴 명사 나열은 조사와 절로 관계를 풀어 쓴다. “서버 연결 오류 확인”은 “서버에 연결할 때 발생한 오류를 확인하세요”처럼 바꿀 수 있지만, 실제로 연결 중 발생한 오류인지 먼저 확인한다.

### 행동, 조건, 순서

- 절차에서는 한 단계에 하나의 주요 행동을 둔다. 서로 독립적인 행동은 번호 목록으로 나눈다. 동시에 해야 하는 행동은 그 관계가 사라지지 않도록 함께 설명한다.
- 행동 전에 알아야 하는 조건이나 경고는 행동보다 먼저 제시한다. “A이면 B”를 “A를 확인하고 B”로 바꿔 원문에 없는 작업을 추가하지 않는다.
- “설정 변경을 수행하세요”보다 “설정을 변경하세요”처럼 직접적인 동사를 쓴다. 가능하면 행동 주체가 분명한 문장으로 작성하되, 자연스러운 한국어 상태 표현이나 필요한 수동 표현을 일괄 금지하지 않는다.
- 부정의 적용 범위를 명확하게 쓴다. “A와 B를 삭제하지 마세요”에서 둘 모두를 금지하는지 불명확하면 근거를 확인한다.
- 경고의 위험 종류와 예방 행동을 보존한다. 간결하게 만들기 위해 경고를 삭제하거나 의무를 권고로 완화하지 않는다.

### 길이와 구체성

- 한 문장에는 하나의 핵심 내용을, 한 문단에는 하나의 주제를 둔다. 조건·이유·결과를 나눌 때 서로의 관계가 유지되는지 확인한다.
- 영어의 문장당 20·25단어, 명사 묶음 3단어 제한을 한국어 어절 수에 그대로 적용하지 않는다. 사용자가 별도 길이 기준을 주면 따르고, 그렇지 않으면 이해하기 어려운 긴 문장을 중심으로 분리한다.
- “적절히”, “충분히”, “잠시” 같은 표현은 근거가 있는 기준으로 구체화한다. 기준을 모르면 임의의 숫자로 대체하지 않는다.
- 절차에는 번호 목록을, 동일 항목의 비교에는 표를 사용한다. 설명문까지 모두 체크리스트로 바꾸지 않는다.
- 기존 종결형을 일관되게 유지한다. 지정된 문체가 없으면 절차는 “확인하세요”, 설명은 “반환합니다”처럼 자연스러운 문체를 선택한다.

## 수행과 결과

1. 문서 목적, 독자, 수정 범위를 파악한다. 제공된 자료로 알 수 있는 내용을 다시 묻지 않는다.
2. 절차와 설명을 구분하고 주요 용어, 조건, 수치, 예외를 확인한 뒤 작성하거나 교정한다.
3. 결과를 원문 또는 근거와 비교한다. 특히 단계 분리나 문장 재구성으로 조건, 의무, 실행 순서가 달라지지 않았는지 검토한다.

작성·교정 요청에는 완성된 문서를 우선 제공한다. 중요한 의미 확인 사항이 있으면 따로 표시한다. 검토만 요청받았다면 문서를 수정하지 말고 문제 구절, 해석 위험, 수정 제안을 제시한다. 전후 비교나 수정 이유는 요청됐거나 중요한 변경을 설명할 때 제공한다.

## 예시

**명사형 표현 줄이기**

- 원문: 설정 변경을 수행한 후 서버 재시작을 진행하세요.
- 수정: ① 설정을 변경하세요. ② 서버를 재시작하세요.

**조건과 의무 보존하기**

- 원문: 모델 로딩이 완료된 경우에만 추론 작업을 반드시 시작해야 합니다.
- 수정: 모델 로딩이 완료된 경우에만 추론을 시작해야 합니다.
- 주의: “추론을 시작할 수 있습니다”는 의무를 허용으로 바꾸므로 같은 의미가 아니다.

**수치와 동시 실행 보존하기**

- 원문: 온도가 80°C 이상이면 가열을 중지하고, 냉각 중에는 펌프와 팬을 동시에 작동시키세요.
- 수정: 온도가 80°C 이상이면 가열을 중지하세요. 냉각 중에는 펌프와 팬을 동시에 작동시키세요.
- 주의: “80°C를 초과하면”으로 바꾸거나 펌프와 팬을 순차 실행 단계로 나누면 의미가 달라진다.

**알 수 없는 기준 남기기**

- 원문: 충분히 냉각된 후 덮개를 여세요.
- 처리: 온도나 완료 기준이 자료에 없다면 문구를 유지하고 “덮개를 열 수 있는 냉각 완료 기준 확인 필요”를 별도로 적는다.

- [공식 FAQ](https://www.asd-ste100.org/STE_faq.html): 적용 범위와 기술 명사·동사 등 예외.
- [공식 표준 요청 및 AI 활용 안내](https://www.asd-ste100.org/STE_downloads.html): 정식 영어 준수 검토에는 해당 판본의 전체 규칙과 사전을 확인한다.

한국어 문서에 승인 영어 단어 목록을 강제하거나, 이 가이드에 따른 결과를 “ASD-STE100 준수”라고 표시하지 않는다. 문장이 명확해졌다는 이유만으로 기술적 정확성이나 이해도 향상이 검증됐다고 주장하지 않는다.
